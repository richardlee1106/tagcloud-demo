# 检查点示例

在 Claude Code 中有效使用检查点的真实案例。

注意：检查点会在每次用户提示时自动创建。您无需手动保存。要回溯，请按 `Esc` 两次（`Esc+Esc`）或使用 `/rewind` 打开检查点浏览器。

## 示例 1：数据库迁移

### 场景
您需要从 MySQL 迁移到 PostgreSQL，但想同时探索直接迁移和渐进式双写方案。

### 工作流

```
User: 让我们实现从 MySQL 到 PostgreSQL 的直接迁移
      [检查点 A 自动创建]

Claude: 我将实现直接迁移...
[更改数据库驱动、更新查询、修改模式]

User: 运行测试
      [检查点 B 自动创建]

Claude: 正在运行测试...
❌ 15 个测试失败 - 连接池问题

User: 这个方案有问题。让我们试试双写模式。
[用户按 Esc+Esc，选择检查点 A，选择"还原代码和对话"]

User: 现在实现双写模式，同时写入两个数据库

Claude: 我将实现双写迁移...
[实现双写层，渐进式迁移策略]

User: 运行测试

Claude: 正在运行测试...
✅ 所有测试通过

User: 双写方案明显更安全。让我们提交吧。
```

## 示例 8：使用"从这里总结"

### 场景
经过长时间的调试会话后，您想在保留上下文的同时压缩对话。

### 工作流

```
User: [经过 20+ 条调试和探索消息后]

[用户按 Esc+Esc，选择一个早期检查点，选择"从这里总结"]
[可选地提供说明："重点关注我们尝试了什么，什么有效"]

Claude: [生成从该时间点之后对话的摘要]
[原始消息保留在转录中]
[摘要替换可见的对话，减少上下文窗口使用]

User: 现在让我们继续使用有效的方案。
```

## 关键要点

1. **检查点是自动的**：每次用户提示都会创建检查点——无需手动保存
2. **使用 Esc+Esc 或 /rewind**：这是访问检查点浏览器的两种方式
3. **选择正确的还原选项**：根据需要还原代码、对话、两者，或使用总结
4. **不要害怕实验**：检查点使尝试激进变更变得安全
5. **与 git 结合使用**：用检查点进行探索，用 git 保存最终确定的变更
6. **总结长会话**：使用"从这里总结"来保持对话可管理
