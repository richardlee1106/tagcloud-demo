# 检查点与回溯

检查点（Checkpoints）允许您保存对话状态，并在 Claude Code 会话中回溯到之前的任意时刻。这对于探索不同方案、从错误中恢复或比较多种替代解决方案非常有价值。

## 概述

检查点允许您保存对话状态并回溯到之前的任意时刻，从而实现安全的实验和多方案的探索。它们是对话状态的快照，包括：
- 所有已交换的消息
- 已进行的文件修改
- 工具使用历史
- 会话上下文

检查点在探索不同方案、从错误中恢复或比较多种替代解决方案时非常宝贵。

## 核心概念

| 概念 | 描述 |
|---------|-------------|
| **检查点（Checkpoint）** | 对话状态的快照，包含消息、文件和上下文 |
| **回溯（Rewind）** | 返回到之前的检查点，丢弃后续的变更 |
| **分支点（Branch Point）** | 从中探索多种方案的检查点 |

## 访问检查点

您可以通过两种主要方式访问和管理检查点：

### 使用键盘快捷键
按两次 `Esc`（`Esc` + `Esc`）打开检查点界面，浏览已保存的检查点。

### 使用斜杠命令
使用 `/rewind` 命令（别名：`/checkpoint`）进行快速访问：

```bash
# 打开回溯界面
/rewind

# 或使用别名
/checkpoint
```

## 回溯选项

回溯时会显示五个选项菜单：

1. **还原代码和对话（Restore code and conversation）** -- 将文件和消息都还原到该检查点
2. **还原对话（Restore conversation）** -- 仅回溯消息，保持当前代码不变
3. **还原代码（Restore code）** -- 仅还原文件变更，保持完整的对话历史
4. **从这里总结（Summarize from here）** -- 将此时间点之后的对话压缩成 AI 生成的摘要。原始消息保留在转录中。您可以提供说明，将摘要集中在特定主题上。
5. **算了（Never mind）** -- 取消并返回当前状态

## 自动检查点

Claude Code 会自动为您创建检查点：

- **每个用户提示** - 每次用户输入都会创建一个新检查点
- **持久化** - 检查点跨会话持久保存
- **自动清理** - 检查点在 30 天后自动清理

这意味着您始终可以回溯到对话中的任意历史时刻，从几分钟前到几天前的状态都可以。

## 使用场景

| 场景 | 工作流 |
|----------|---------|
| **探索方案** | 保存 → 尝试方案 A → 保存 → 回溯 → 尝试方案 B → 比较 |
| **安全重构** | 保存 → 重构 → 测试 → 若失败：回溯 |
| **A/B 测试** | 保存 → 设计 A → 保存 → 回溯 → 设计 B → 比较 |
| **错误恢复** | 发现问题 → 回溯到最后一次良好状态 |

## 使用检查点

### 查看和回溯

按 `Esc` 两次或使用 `/rewind` 打开检查点浏览器。您将看到所有可用检查点的列表及其时间戳。选择任意检查点即可回溯到该状态。

### 检查点详情

每个检查点显示：
- 创建时的时间戳
- 被修改的文件
- 对话中的消息数量
- 使用的工具

## 实用示例

### 示例 1：探索不同方案

```
User: 让我们为 API 添加缓存层

Claude: 我将为您的 API 端点添加 Redis 缓存...
[在检查点 A 进行变更]

User: 实际上，我们来试试内存缓存

Claude: 我将回溯以探索另一种方案...
[用户按 Esc+Esc 并回溯到检查点 A]
[在检查点 B 实现内存缓存]

User: 现在我可以比较两种方案了
```

### 示例 2：从错误中恢复

```
User: 将认证模块重构为使用 JWT

Claude: 我将重构认证模块...
[进行了大量变更]

User: 等等，这破坏了 OAuth 集成。我们回去吧。

Claude: 我来帮您回溯到重构之前...
[用户按 Esc+Esc，选择重构前的检查点]

User: 这次我们试试更保守的方案
```

### 示例 3：安全实验

```
User: 我们来试试用函数式风格重写这个
[在实验前创建检查点]

Claude: [进行实验性变更]

User: 测试失败了。我们回溯吧。
[用户按 Esc+Esc 并回溯到检查点]

Claude: 我已回滚变更。让我们试试不同的方案。
```

### 示例 4：分支探索

```
User: 我想比较两种数据库设计方案
[记下检查点——称之为"起点"]

Claude: 我来创建第一个设计...
[实现方案 A]

User: 现在让我回去尝试第二种方案
[用户按 Esc+Esc 并回溯到"起点"]

Claude: 现在我来实现方案 B...
[实现方案 B]

User: 很好！现在我有两个方案可以选择了
```

## 检查点保留

Claude Code 自动管理您的检查点：

- 每次用户提示都会自动创建检查点
- 旧的检查点最多保留 30 天
- 检查点会被自动清理，以防止存储无限增长

## 工作流模式

### 探索用分支策略

探索多种方案时：

```
1. 从初始实现开始 → 检查点 A
2. 尝试方案 1 → 检查点 B
3. 回溯到检查点 A
4. 尝试方案 2 → 检查点 C
5. 比较 B 和 C 的结果
6. 选择最佳方案并继续
```

### 安全重构模式

进行重大变更时：

```
1. 当前状态 → 检查点（自动）
2. 开始重构
3. 运行测试
4. 若测试通过 → 继续工作
5. 若测试失败 → 回溯并尝试不同方案
```

## 最佳实践

由于检查点是自动创建的，您可以专注于工作，而无需担心手动保存状态。但请记住以下实践：

### 有效使用检查点

✅ **推荐做法：**
- 回溯前查看可用的检查点
- 想探索不同方向时使用回溯
- 保留检查点以比较不同方案
- 了解每个回溯选项的作用（还原代码和对话、还原对话、还原代码或总结）

❌ **不推荐做法：**
- 仅依赖检查点来保存代码
- 期望检查点追踪外部文件系统变更
- 用检查点代替 git 提交

## 配置

您可以在设置中切换自动检查点：

```json
{
  "autoCheckpoint": true
}
```

- `autoCheckpoint`：启用或禁用每次用户提示时自动创建检查点（默认：`true`）

## 限制

检查点有以下限制：

- **Bash 命令变更不追踪** - 文件系统上的 `rm`、`mv`、`cp` 等操作不会在检查点中捕获
- **外部变更不追踪** - 在 Claude Code 外部（编辑器、终端等）进行的变更不会被捕获
- **不能替代版本控制** - 使用 git 来管理代码库中永久可审计的变更

## 故障排除

### 找不到检查点

**问题**：找不到预期的检查点

**解决方案**：
- 检查检查点是否已被清除
- 确认设置中 `autoCheckpoint` 已启用
- 检查磁盘空间

### 回溯失败

**问题**：无法回溯到检查点

**解决方案**：
- 确保没有未提交的变更冲突
- 检查检查点是否损坏
- 尝试回溯到其他检查点

## 与 Git 集成

检查点补充（但不替代）git：

| 特性 | Git | 检查点 |
|---------|-----|-------------|
| 范围 | 文件系统 | 对话 + 文件 |
| 持久性 | 永久 | 基于会话 |
| 粒度 | 提交 | 任意时刻 |
| 速度 | 较慢 | 即时 |
| 共享 | 支持 | 有限 |

两者结合使用：
1. 使用检查点进行快速实验
2. 使用 git 提交最终确定的变更
3. 在 git 操作前创建检查点
4. 将成功的检查点状态提交到 git

## 快速入门

### 基本工作流

1. **正常工作** - Claude Code 自动创建检查点
2. **想回去？** - 按 `Esc` 两次或使用 `/rewind`
3. **选择检查点** - 从列表中选择要回溯的检查点
4. **选择还原内容** - 选择还原代码和对话、还原对话、还原代码、从这里总结或取消
5. **继续工作** - 您已回到该时间点

### 键盘快捷键

- **`Esc` + `Esc`** - 打开检查点浏览器
- **`/rewind`** - 访问检查点的替代方式
- **`/checkpoint`** - `/rewind` 的别名

## 何时回溯：上下文监控

检查点让您可以返回——但您怎么知道什么时候应该这样做？随着对话增长，Claude 的上下文窗口会填满，模型质量会在不知不觉中下降。您可能在用一个半盲的模型在写代码。

**[cc-context-stats](https://github.com/luongnv89/cc-context-stats)** 通过在 Claude Code 状态栏中添加实时**上下文区域**来解决这个问题。它追踪您在上下文窗口中的位置——从**Plan**（绿色，安全进行规划和编码）到**Code**（黄色，避免开始新计划）再到**Dump**（橙色，结束工作并回溯）。当您看到区域发生变化时，就知道是时候创建检查点并重新开始了，而不是在下降的输出中继续推进。

## 摘要

检查点是 Claude Code 中的自动功能，让您可以安全地探索不同方案，而不必担心丢失工作。每次用户提示都会自动创建一个新检查点，因此您可以回溯到会话中的任意历史时刻。

主要优势：
- 大胆尝试多种方案
- 快速从错误中恢复
- 并排比较不同的解决方案
- 与版本控制系统安全集成

记住：检查点不能替代 git。将检查点用于快速实验，将 git 用于永久的代码变更。
