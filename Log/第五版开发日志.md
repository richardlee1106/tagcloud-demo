### 2.1 deck.gl 高性能渲染重构

**技术栈**：deck.gl (@deck.gl/core, @deck.gl/layers, @deck.gl/aggregation-layers), OpenLayers

**背景问题**：

- 原有 OpenLayers VectorLayer 在渲染数万个 POI 点时出现明显卡顿。
- 热力图 (ol/layer/Heatmap) 在大数据量下同样存在性能瓶颈。
- 地图拖拽和交互不流畅。

**实现逻辑**：

1.  **混合渲染架构**：保留 OpenLayers 处理底图、绘制交互和特殊标记（五角星），使用 deck.gl 处理高性能批量渲染。

    ```javascript

    // - 底图瓦片 (TileLayer)
    // - 绘制交互 (Draw Interaction)
    // - 定位五角星 (locateLayer)

    // deck.gl 负责：
    // - POI 点渲染 (ScatterplotLayer)
    // - 热力图渲染 (HeatmapLayer)
    ```

2.  **deck.gl 初始化**：在 OpenLayers 地图容器上叠加 deck.gl canvas。

    ```javascript
    deckContainer = document.createElement("div");
    deckContainer.style.cssText = `
      position: absolute;
      pointer-events: none;  // 不阻挡 OpenLayers 交互
      z-index: 1;
    `;

    deckInstance = new Deck({
      parent: deckContainer,
      controller: false, // 禁用 deck.gl 自带控制器
      layers: [],
    });
    ```

3.  **视图同步**：监听 OpenLayers 视图变化，实时同步到 deck.gl。

    ```javascript
    function syncDeckView() {
      const view = map.getView();
      const center = toLonLat(view.getCenter());
      deckInstance.setProps({
        viewState: {
          longitude: center[0],
          latitude: center[1],
          zoom: view.getZoom() - 1, // deck.gl zoom 偏移
          bearing: (-view.getRotation() * 180) / Math.PI,
        },
      });
    }

    map.getView().on("change:resolution", syncDeckView);
    map.getView().on("change:center", syncDeckView);
    ```

4.  **POI 图层 (ScatterplotLayer)**：


5.  **热力图图层 (HeatmapLayer)**：

## 3. 취

###  1λ½

- **现象**：几万个标签时，点击 POI 触发 `centerOnFeature` 会使浏览器卡死。
- **原因**：`centerOnFeature` 使用 `rootGroupRef.selectAll('text').each()` 遍历所有 DOM 元素，时间复杂度 O(n) 但 DOM 操作极慢。
- **解决**：
  1.  缓存布局数据 `cachedLayoutTags` 在内存中。
  2.  ʹƥڴпٲң DOM
  3.  移除 POI → 标签的定位动画（只保留橙色常亮）。

### 问题 2：POI 圆圈与五角星叠加显示

- **现象**：定位时，水蓝色五角星与红色圆圈同时显示。
- **原因**：deck.gl 的 ScatterplotLayer 没有过滤掉当前定位的 POI。
- **解决**：
  1.  在 `flyTo` 中记录 `currentLocatedPoi`。
  2.  在 `updateDeckLayers` 的 `data` 参数中过滤掉该 POI。
  3.  使用 OpenLayers 的 `locateLayer` 单独显示五角星。

###  3뿪ǩʧ

- **现象**：点击 POI 后对应标签高亮，但鼠标离开 POI 后标签恢复原色。
- **原因**：只使用了一个 `hoveredFeatureId` 状态，鼠标离开时被清空。
- **解决**：
  1.  新增 `clickedFeatureId` 状态用于点击常亮。
  2.  `updateHighlight` 函数同时检查两个状态，点击优先级更高。

###  4ǩص

- **现象**：使用搜索工具过滤后，标签之间出现碰撞重叠。
- **原因**：D3 的 key 函数使用 `originalIndex`，搜索后新旧数据的 key 冲突导致 DOM 元素错误复用。
- **解决**：使用更唯一的 key：`${d.name}-${d.lon?.toFixed(6)}-${d.lat?.toFixed(6)}`。

## 6. 地理感知标签云布局算法重构

### 6.1 问题背景

圆形绘制工具存在以下问题：

1.  **λ**POI ڵͼϵķλޣڱǩδ 100% ȷ
2.  **地图拖拽影响标签云**：拖动地图时，右侧标签云布局会意外改变
3.  ** POI ײ** 1000  POI ʱص
4.  **布局方向偏差**：POI 多时算法倾向于垂直方向放置

### 6.2 算法重构方案

**技术栈**：Web Worker, OffscreenCanvas, 自定义螺旋搜索算法

**核心原则**：

1.  **方位保持**：标签必须保持在相对于中心的正确象限（东南西北）
2.  **距离保持**：标签距离中心的远近应反映地理距离
3.  **ײ**ǩ֮䲻صײƻԼ
4.  **不依赖地图视图**：完全基于经纬度计算，不受拖拽/缩放影响

### 6.3 实现逻辑

#### 1. 预处理：计算地理属性

```javascript
// 经度校正因子（1度经度的实际距离随纬度变化）
const latRad = (centerLat * Math.PI) / 180;
const lonFactor = Math.cos(latRad);

// 地理偏移
const dLon = (tag.lon - centerLon) * lonFactor;
const dLat = tag.lat - centerLat;

// 地理距离和角度
const geoDistance = Math.sqrt(dLon * dLon + dLat * dLat);
const geoAngle = Math.atan2(dLat, dLon);

// 确定象限
// 1 = 东北 → 屏幕右上
// 2 = 西北 → 屏幕左上
// 3 = 西南 → 屏幕左下
// 4 = 东南 → 屏幕右下
```

#### 2. 目标位置计算

```javascript
// 归一化距离
const normalizedDistance =
  (geoDistance / maxGeoDistance) * availableRadius * 0.9;

// 屏幕坐标（Y 轴反转：纬度增加 → 屏幕 Y 减少）
const targetX = centerX + normalizedDistance * Math.cos(geoAngle);
const targetY = centerY - normalizedDistance * Math.sin(geoAngle);
```

#### 3. 螺旋搜索（保持象限约束）

```javascript
function findValidPosition(tag, placedTags, cx, cy, ...) {
    let theta = 0;

    while (attempt < maxAttempts) {
        // 螺旋轨迹
        const r = spiralStep * theta / (2 * Math.PI);
        const testX = tag.targetX + r * Math.cos(theta);
        const testY = tag.targetY + r * Math.sin(theta);

        // 检查象限约束
        if (!verifyQuadrant(testX, testY, cx, cy, tag.quadrant)) {
            theta += 0.3;
            continue;
        }

        // 检查碰撞
        if (!hasCollision(testX, testY, ...)) {
            return { x: testX, y: testY };
        }

        theta += 0.3;
    }
}
```

#### 4. 象限验证与强制修正

```javascript
function verifyQuadrant(x, y, cx, cy, targetQuadrant) {
  const isRight = x >= cx; // 东
  const isUp = y <= cy; // 北（屏幕 Y 反转）

  switch (targetQuadrant) {
    case 1:
      return isRight && isUp; // 东北
    case 2:
      return !isRight && isUp; // 西北
    case 3:
      return !isRight && !isUp; // 西南
    case 4:
      return isRight && !isUp; // 东南
  }
}

// 最终验证，确保 100% 正确
if (!isCorrectQuadrant) {
  const corrected = forceCorrectQuadrant(d, centerX, centerY);
  d.x = corrected.x;
  d.y = corrected.y;
}
```

## 7. 高亮响应优化

### 7.1 问题描述

悬浮和点击 POI 时，右侧对应的标签高亮有延迟，甚至时灵时不灵。

### 7.2 原因分析

1.  `requestAnimationFrame` 防抖导致延迟
2.  `findIndex` 使用坐标匹配精度不够，导致匹配失败
3.  遍历 `props.data` 而非使用缓存的 `cachedLayoutTags`

### 7.3 优化方案

```javascript
function updateHighlight() {
  // 移除防抖，直接执行
  if (!rootGroupRef || rootGroupRef.empty()) return;

  // 使用缓存的布局数据快速查找
  const findMatchingIndex = (feature) => {
    const coords = feature.geometry?.coordinates;

    // 在缓存的布局数据中查找（精度放宽到 0.0001）
    for (const tag of cachedLayoutTags) {
      if (
        Math.abs(tag.lon - coords[0]) < 0.0001 &&
        Math.abs(tag.lat - coords[1]) < 0.0001
      ) {
        return tag.originalIndex;
      }
    }
    return -1;
  };

  // ... 更新样式
}

// 同步 watcher，确保立即响应
watch(
  () => props.hoveredFeatureId,
  () => updateHighlight(),
  { flush: "sync" }
);
watch(
  () => props.clickedFeatureId,
  () => updateHighlight(),
  { flush: "sync" }
);
```

### 7.4 优化效果

| 优化项   | 优化前                        | 优化后                  |
| -------- | ----------------------------- | ----------------------- |
| 响应延迟 | ~16ms (requestAnimationFrame) | 即时 (sync)             |
| 匹配精度 | 0.000001                      | 0.0001 (更宽容)         |
| 数据源   | props.data (可能引用不同)     | cachedLayoutTags (可靠) |
