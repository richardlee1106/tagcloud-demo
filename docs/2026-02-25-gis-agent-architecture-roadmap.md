# GIS Agent 架构创新路线图（2026-02-25）

## 1. 当前瓶颈判断（基于现状推断）
- 端到端耗时偏高：同一次对话内存在重复空间计算，热点/片区/模糊边界派生指标复算率高。
- 意图路由较“静态”：`query_type/intent_mode` 可用，但模板/分析策略仍以规则为主，难以随真实用户行为自适应。
- 数据契约弹性不足：SSE 事件语义可用，但缺乏版本化策略与能力声明，前后端演进耦合较紧。
- 可观测性偏薄：缺少“每阶段耗时 + 命中率 + 质量回传”闭环，优化迭代成本高。

## 2. 路线总览（成本-风险-收益）
| 路线 | 核心目标 | 成本 | 风险 | 预期收益 |
|---|---|---|---|---|
| 路线A：渐进增强 | 低风险提速 + 质量稳步提升 | 低-中 | 低 | 延迟下降 25%-40%，稳定性明显提升 |
| 路线B：性能优先重构 | 将空间计算与推理解耦，显著提速 | 中-高 | 中 | 延迟下降 45%-65%，高并发吞吐提升 |
| 路线C：能力跃迁 | 从“问答”升级为“可执行 GIS 决策系统” | 高 | 中-高 | 复杂任务成功率大幅提升，形成长期护城河 |

结论建议：先落地路线A，3-6周后评估是否切入路线B；路线C以并行预研方式推进。

## 3. 算法改进建议
### 3.1 意图路由（Intent Router v2）
- 做法：主意图固定（宏观/微观/对比）+ 子意图学习化分类（轻量模型或规则+校正器）。
- 关键点：将用户问题、地图上下文、历史会话压缩成统一特征向量。
- 收益：模板命中率和回答“相关性”提升，减少无效计算。

### 3.2 模板选择学习化（LTR-lite）
- 做法：保留规则兜底，引入轻量重排器（Learning-to-Rank）对候选模板 Top-K 重排。
- 在线信号：用户点击定位、追问率、停留时长、二次编辑率。
- 收益：模板选择从“工程经验”变为“可学习策略”，持续自优化。

### 3.3 空间计算热点优化
- 做法：
  - 预聚合：按 H3/S2 网格维护热点/业态统计快照。
  - 增量计算：仅对变化视野和新增数据重算。
  - 结果缓存：按 `intent + spatial_hash + zoom + category` 分层缓存。
- 收益：同类问题响应时间显著下降，降低后端算力成本。

## 4. 技术栈变更候选
## 4.1 候选一：维持现栈做性能增强（推荐起步）
- 方案：Node/Python 现有服务不拆，先补缓存、并行、观测。
- 成本：低；风险：低；适配速度最快。

## 4.2 候选二：空间计算服务独立（Go/Rust）
- 方案：将聚类、边界建模、重叠辐射计算拆成独立高性能服务。
- 成本：中-高；风险：中（跨语言维护、部署复杂度上升）。
- 收益：CPU 密集任务提速明显，长远可扩展性更好。

## 4.3 候选三：能力层升级（检索 + 规划）
- 方案：增加“知识检索层 + 任务规划层”，形成可解释的执行计划。
- 成本：高；风险：中-高（引入更多系统组件）。
- 收益：复杂决策链路质量明显提升，支持更强的企业场景。

## 5. 架构优化重点
### 5.1 契约版本化
- 建议：SSE 增加 `schema_version` 与 `capabilities` 字段。
- 价值：前后端灰度演进可控，减少“改一端炸全链路”。

### 5.2 异步流水线与缓存分层
- L1：会话内内存缓存（秒级复用）
- L2：进程/节点缓存（分钟级）
- L3：离线预计算快照（小时级）
- 价值：降低重复计算，提升高峰期稳定性。

### 5.3 可观测性体系
- 指标：阶段耗时、失败率、重试率、缓存命中率、模板点击率、追问转化率。
- 追踪：为每次对话生成 `trace_id`，串联前端事件与后端算子耗时。
- 价值：定位慢点和质量问题的时间显著缩短。

## 6. 里程碑（建议）
### M1（2026-03-01 至 2026-03-21）
- 交付：Intent Router v2、模板重排器 v1（规则+轻量学习）、L1/L2 缓存、核心观测看板。
- 验收阈值：
  - P95 首次响应时延下降 >= 25%
  - 模板点击率提升 >= 15%
  - SSE 解析/契约错误率下降 >= 40%

### M2（2026-03-22 至 2026-04-30）
- 交付：空间计算增量化、热点预聚合、关键算子并行化。
- 验收阈值：
  - P95 端到端时延下降 >= 45%
  - CPU 单次请求成本下降 >= 30%

### M3（2026-05-01 至 2026-06-30，预研+试点）
- 交付：能力层（检索+规划）试点，复杂任务策略编排。
- 验收阈值：
  - 复杂查询成功率提升 >= 20%
  - 用户二次追问中的“纠错型追问”下降 >= 25%

## 7. KPI 体系（速度 / 质量 / 稳定性）
| 维度 | KPI | 目标 |
|---|---|---|
| 速度 | P50/P95 首次 token 时延 | P95 < 3.5s（阶段A），< 2.5s（阶段B） |
| 速度 | 完整回答端到端时延 | 降低 40%-60% |
| 质量 | 模板命中满意度 | 提升 20%+ |
| 质量 | 追问有效率（有用追问占比） | 提升 15%+ |
| 稳定性 | SSE 事件错误率 | < 0.5% |
| 稳定性 | 线上故障恢复时间（MTTR） | 降低 30%+ |

## 8. 推荐实施顺序
1. 先做路线A（低风险高回报），快速建立“可观测 + 可学习 + 可缓存”的基础设施。
2. 在路线A达到 KPI 后，按热点算子选择性推进路线B（而非一次性全量重构）。
3. 路线C保持小范围试点，验证业务价值后再扩展到主链路。
