## 目标

- 在 `V4-GeoLoom-beta` 内搭建独立 Node/TypeScript 服务。
- 建立统一的 skill 合约、注册中心和调试接口。
- 落地 `postgis_skill` 最小闭环。
- 实现 SQL 安全三层锁最小可用版。
- 补齐 Phase 0-1 所需单元测试与基础集成测试。

## 非目标

- 不实现 `POST /api/geo/chat`。
- 不接入 LLM Provider、Function Calling、Alive Prompt、Memory、Evidence View。
- 不实现前端 SSE 联调。
- 不落地 `spatial_encoder_skill`、`spatial_vector_skill`、`route_distance_skill`。
- 不修改 `V1-fastify-backend` 与 `V3-GeoEncoder-RAG` 的主运行入口。

## Phase 0-1 任务顺序

1. 搭建 `V4-GeoLoom-beta` 工程骨架与测试配置。
2. 定义 skill 类型、执行上下文与 `SkillRegistry`。
3. 搭建 `createApp()`、健康检查与 skills 调试路由。
4. 实现 `postgis_skill` 统一 action 合约。
5. 实现 `get_schema_catalog`、`resolve_anchor`、`validate_spatial_sql`、`execute_spatial_sql`。
6. 在 `SQLSandbox` 中集中落地 SQL 安全三层锁。
7. 通过 `tests/unit/*` 与 `tests/integration/*` 验证 Phase 0-1 闭环。

## 验收标准

- `V4-GeoLoom-beta` 可独立启动。
- `GET /api/geo/health` 可返回版本、数据库状态、已注册 skill 数量。
- `GET /api/geo/skills` 可列出 `postgis` 及其 action。
- `POST /api/geo/skills/postgis/call` 可执行最小闭环 action。
- `execute_spatial_sql` 必须经过 SQL 安全三层锁。
- 单元测试与基础集成测试可运行通过。
