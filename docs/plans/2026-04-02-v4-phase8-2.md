## 4. 关键修复

### 4.1 锚点字段漂移

- 真实 provider 的 tool payload 并不稳定，先后出现过：
  - `anchor_text`
  - `anchor_name`
  - `anchor`
- 修复策略：
  - 不把字段名假设散落在 agent / route 层
  - 集中收口到 `postgis.resolve_anchor` skill 边界兼容

### 4.2 核心题型兜底

- 真实 LLM 偶尔会调用：
  - 非白名单 SQL
  - 错误类别过滤
  - 偏离 `postgis` 主链的 mock skill
- 修复策略：
  - 对 `nearby_poi / nearest_station / compare_places` 增加确定性 postgis recovery
  - 一旦检测到证据缺失或证据与意图不对齐，自动回退到模板化只读 SQL
  - recovery 命中时优先返回 renderer 的确定性答案，不让空泛 LLM 文本覆盖真实证据

### 4.3 Windows 一键启动

- 原问题：
  - Windows 下 shell 拼接的 `npx concurrently "..." "..."` 被 `cmd.exe` 拆碎
- 修复策略：
  - 改为 Node 直接 spawn 两个子进程
  - 前端：`cmd.exe /d /s /c npm run dev:frontend:v4`
  - 后端：`cmd.exe /d /s /c npm run dev`
  - 统一前缀日志输出，便于排查
