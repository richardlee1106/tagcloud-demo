## 1. 顶层目录与全局工程文件（Root Scope）

### 1.1 顶层目录职责（按性质分类）

| 路径 | 性质 | 作用与边界 |
|---|---|---|
| `.agent/` | Agent 运行资产 | 本地代理/工具链运行时目录，非业务代码。通常包含会话状态、临时缓存等。 |
| `.agents/` | Agent 技能库 | 技能定义目录（含 `SKILL.md` 等），为智能体执行流程提供可复用方法，不参与前后端运行时。 |
| `.bitfun/` | 工具配置 | IDE/插件或辅助工具目录，非业务逻辑。 |
| `.claude/` | Agent 配置 | 与协作代理有关的配置和上下文，不是应用运行依赖。 |
| `.codex/` | Agent 配置/技能 | 本地 Codex 扩展能力配置和技能，非业务。 |
| `.git/` | 版本控制元数据 | Git 对象库、引用、hooks、日志。不能当业务配置修改。 |
| `.kilocode/` | 工具目录 | 本地工具辅助目录，不影响运行链路。 |
| `.kiro/` | 工具目录 | 本地工具辅助目录，不影响运行链路。 |
| `.vscode/` | IDE 配置 | VS Code 工作区配置（调试、推荐扩展等），不参与打包。 |
| `.zed/` | IDE 配置 | Zed 编辑器配置目录。 |
| `dist/` | 构建产物 | Vite 前端打包结果；可部署，不应手改。 |
| `docker/` | 容器构建 | 放置 DB 镜像构建文件（如 PostGIS/pgvector 扩展镜像）。 |
| `docker-init-spatial/` | DB 初始化 SQL | 空间数据库初始化脚本目录，容器首次启动时执行。 |
| `docs/` | 项目文档 | 架构、迁移、评审等文本文档。包含阶段性报告。 |
| `fastify-backend/` | 后端主代码 | Fastify API 网关、路由、服务、队列、Python 计算桥接核心。 |
| `Log/` | 开发日志资产 | 迭代日志、问题复盘、历史实现记录；偏过程文档。 |
| `newdata/` | 数据资产 | 业务相关空间数据（GeoJSON）输入源。 |
| `nginx-1.28.1/` | 第三方发行包 | Nginx 压缩/解压后的发行目录，通常用于本地反向代理实验。 |
| `node_modules/` | 前端依赖 | 根前端依赖安装结果，非手写代码。 |
| `public/` | 前端静态资源 | Vite 静态目录，原样拷贝到构建产物。 |
| `RAG_LOG/` | 运行日志数据 | RAG/推理链路落盘日志目录。 |
| `scripts/` | 根级脚本目录 | 根目录脚本（通常是 SQL 或辅助初始化脚本入口）。 |
| `shared/` | 跨端共享契约 | 前后端共用 schema（当前核心是 SSE 事件契约）。 |
| `src/` | 前端源代码 | Vue3 应用入口、视图、组件、worker、工具函数。 |
| `用于比较数据/` | 对比数据资产 | 实验/对照样本目录，用于模型或结果比对。 |

| 文件 | 性质 | 作用 |

## 6. 运行链路、文件分工边界与最小可运行集合

### 6.1 启动链路（本地开发）

1. 前端：根 `package.json` 脚本 `dev:frontend` 启动 Vite。
2. 后端：`fastify-backend/server.js` 初始化 DB / 向量能力 / 队列并注册 API。
3. Python：`python_service/grpc_server.py` 提供空间计算流式服务。
4. 数据库：由 docker compose 与 SQL 脚本提供 PostGIS/pgvector 能力。

### 6.2 查询执行链路（高频主路径）

1. 前端 `AiChat.vue` / `aiService.js` 发起 `/api/ai/chat`。
2. 后端 `routes/ai/index.js` 进入 SSE 流。
3. `services/spatialJobRunner.js` 串联 planner -> compute -> writer。
4. 计算阶段经 `services/grpcClient.js` 调用 Python gRPC。
5. Python pipeline 计算后返回 `FINAL/PROGRESS/STAGE` 事件。
6. Node 归一化并通过 SSE 分发给前端；前端组件映射为证据/图层/文本。

### 6.3 文件分工边界（避免职责漂移）

- `routes/*`：仅做协议边界、参数校验、响应格式控制。
- `services/*`：承载业务策略与跨模块编排。
- `python_service/*`：承载重计算与空间算法。
- `shared/*`：承载跨端契约，避免前后端 schema 漂移。
- `scripts/*`：离线任务/运维工具，不应与在线请求路径耦合。

### 6.4 最小可运行文件集合（实用视角）

如果目标是“能跑通主流程（前端 -> 后端 -> Python -> DB）”，最小集合包括：

- 前端：`src/**`、`index.html`、`package.json`、`vite.config.js`
- 后端：`fastify-backend/server.js`、`fastify-backend/routes/**`、`fastify-backend/services/**`、`fastify-backend/package.json`
- Python：`fastify-backend/python_service/**`、`fastify-backend/proto/spatial_compute.proto`
- 契约：`shared/sseEventSchema.js`
- 基础配置：`.env`、`docker-compose*.yml`、`docker/**`、`fastify-backend/sql/**`

### 6.5 可安全归档（非主运行必需，按需保留）

- `temp_diff*.txt` 临时差异文件
- 部分历史日志/报告（`Log/**`、`reports/**`）
- 压缩备份 `fastify-backend.tar.gz`
- 大量评估输出 `python_service/scripts/eval_output/**`
