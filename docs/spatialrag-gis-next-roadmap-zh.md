# SpatialRAG + GIS 下一阶段开发路线图（中文）

> 更新时间：2026-02-08
> 
> 目标：在“Node 网关 + Python 空间计算”架构基础上，继续提升**空间智能质量**与**真实可用性能**，并形成可持续迭代的产品化能力。

---

## 1. 当前阶段复盘（现状判断）

### 1.1 架构现状
- **Node**：承担公网入口、会话编排、SSE 输出、任务路由、兼容层（`/api/ai/chat` + `/api/jobs/*`）。
- **Python**：承担空间计算主路径（聚类、边界、membership、区域分析等）。
- **回退链路**：保留 Node SQL fallback，保障 Python 不可用时系统仍可返回结果（有降级但不崩）。

### 1.2 最近一轮“性能收口”已落地项
1. **Planner 快路径前置**：明显简单问题优先规则路径，减少不必要 Router LLM 调用。  
2. **Planner 路由失败兜底**：Router 失败时直接规则回退，避免二次慢调用。  
3. **Writer 预算控制**：按 query_type 动态调整 `temperature/max_tokens`，并限制上下文长度。  
4. **Writer 轻量质量门**：生成后执行幻觉检测，命中高风险时追加“可核验摘要”。  
5. **Runner 结果缓存**：在 JobRunner 主链路接入缓存（含 source_policy 指纹），减少重复空间计算。  

### 1.3 当前瓶颈（结论）
- 空间计算本身已明显快于早期版本，**主要瓶颈转移到 LLM 链路**：
  - Planner Router/Writer 仍是端到端耗时大头。
  - 大上下文回答会造成 token 与延迟抖动。
- Node fallback 的速度很快，但语义与空间解释能力弱，不适合长期作为主路径。

- `python -m compileall fastify-backend/python_service`：通过。
- `smoke:jobs`：通过（sync narrative 可完成）。
- `dual_run_parity_check --samples 1`：通过（all_passed=true）。
- 观测到：
  - Python 主计算平均耗时为毫秒级到百毫秒级（样本波动与 query_type 相关）。

## 3. 下一步技术方向（架构与工程）

## 3.1 架构优化方向
1. **双层推理链路（建议）**  
   - Layer A：超轻 planner/router（规则 + 小模型）负责 query_type、约束判定。  
   - Layer B：证据驱动 writer（大模型）只做表达，不再承担“猜测式推理”。
2. **结果分层交付**  
   - 草图结果（<300ms）+ 精修结果（异步覆盖），保持“秒开感”。
3. **计算与写作解耦缓存**  
   - 缓存“空间证据结果”，不缓存最终自然语言文本（或短期缓存），避免旧文本污染。
4. **可观测性升级**  
   - 对 planner/executor/writer 分别上报 P50/P95、超时率、token 成本、失败原因聚类。

## 3.2 Python 计算服务优化方向
1. **多级缓存**：
   - L1 进程内缓存（小 TTL）
   - L2 Redis（跨实例）
   - L3 PostGIS 物化视图（重聚合）
2. **热点算子拆分**：
   - α-shape、邻接图构建、复杂 membership 评分可逐步做 Numba/Cython/PyO3 热点优化。
3. **I/O 优化**：
   - SQL 先 bbox 再精筛；尽量批量读；减少 Python<->DB 往返次数。
4. **几何序列化优化**：
   - Node↔Python 用 WKB/WKT 二进制传输，减少 JSON 大对象开销。

## 3.3 PostGIS 深化方向
1. 继续完善索引组合（空间 + 类别 + 文本）。
2. 物化视图按查询热度做分层刷新（分钟级/小时级）。
3. 对高频区域启用预聚合（H3 r7/r8/r9）并做冷热分离。

## 4. 空间智能创新方向（算法）

## 4.1 “可解释空间智能”优先
- 每次回答必须携带最小解释链：
  - 数据范围（选区/视野）
  - 类别约束来源（全类/选择器）
  - 关键证据（Top POI / Top 区域）
  - 不确定性提示（数据不足或模型置信低）

## 4.2 多尺度空间推理
- 从单尺度聚类升级为：
  - 小尺度（街区）
  - 中尺度（商圈）
  - 大尺度（城区）
- 通过尺度一致性规则减少“边界漂移”和“不可复现”。

## 4.3 方向语义与拓扑语义融合
- 方向（东/西/南/北） + 拓扑（邻近/连通/跨路网）联合评分。
- 对回答增加“方向证据句”，例如：
  - “目标聚集点相对锚点方位角 65°（东偏北）”。

## 4.4 不确定性量化
- 输出 `confidence` + `evidence_coverage` + `boundary_stability`。
- 高不确定时自动降级为保守回答，避免硬编结论。

## 5. 玩法与产品体验创新方向

1. **对话内“空间证据卡片”**：关键区域/POI 支持一键定位、加入对比。  
2. **“如果…会怎样”滑杆**：动态调整类别权重、步行可达半径、密度阈值，实时看边界变化。  
3. **Narrative 导览模式**：由静态结论升级为“路线化叙事”（起点-过渡-核心区）。  
4. **结果可追溯回放**：保存一次对话的 queryPlan + source_policy + 边界，支持复盘与分享。

## 6. 30/60/90 天实施路线

## 6.1 0-30 天（稳定性 + 成本）
- 目标：把“可用”打磨成“稳定可用”。
- 重点：
  1) 完成 LLM 链路性能预算（planner/writer token 与超时）
  2) 缓存命中率提升（目标 >35%）
  3) 幻觉监控报表（按 query_type 分层）
- 验收：
  - 主路由轻查询 P95 < 1.2s（缓存命中场景显著低于 300ms）
  - 回答幻觉率下降（按自动检测口径）

## 6.2 31-60 天（空间智能增强）
- 目标：提高“空间推理可信度”。
- 重点：
  1) 多尺度区域推理
  2) 方向+拓扑联合打分
  3) 不确定性输出（confidence/evidence coverage）
- 验收：
  - 方向查询正确率 >= 95%
  - 同输入多次运行边界 IoU 偏差 < 2%

## 6.3 61-90 天（产品化创新）
- 目标：提高“可玩性”和“复用率”。
- 重点：
  1) 空间证据卡片与一键对比
  2) 参数滑杆 + what-if
  3) narrative 路线化输出
- 验收：
  - 用户停留时长、复访率、二次提问率明显提升
  - 人工评估“有空间智能感”的比例提升

## 8. 风险与回退策略

1. **风险：性能优化伤害回答质量**  
   - 策略：质量门禁先行（自动评测 + 人工抽检）；一旦下降，回退参数而不是回退全部架构。  
2. **风险：缓存引入错误复用**  
   - 策略：指纹包含 source_policy 与空间约束；高风险 query_type 降低 TTL。  
3. **风险：算法升级导致结果漂移**  
   - 策略：双跑对比、灰度发布、IoU/TopK overlap 达标后再放量。  
4. **风险：Python 服务资源争抢**  
   - 策略：队列限流 + 任务优先级 + 超时降级（先返回草图结果）。
