## 一、架构说明

```
┌─────────────────────────────────────────────────────────────┐
│  新架构流程                                                 │
├─────────────────────────────────────────────────────────────┤
│  Phase 1: 小模型意图理解 (Qwen3.5-0.8b)                     │
│  - 提取类别、语义标签、地点、半径                            │
│  - 耗时：~500ms                                             │
├─────────────────────────────────────────────────────────────┤
│  Phase 2: FAISS 召回 / PostGIS 回退                         │
│  - 空间 + 类别过滤，返回 Top-50                             │
│  - 耗时：~20ms                                              │
├─────────────────────────────────────────────────────────────┤
│  Phase 3: 小模型语义筛选                                     │
│  - 根据语义标签精选 Top-10                                   │
│  - 耗时：~400ms                                             │
├─────────────────────────────────────────────────────────────┤
│  Phase 4: 大模型答案生成                                     │
│  - 组织自然语言回答                                         │
│  - 耗时：~1500ms                                            │
├─────────────────────────────────────────────────────────────┤
│  兜底：小模型不可用时 → 硬编码映射                           │
└─────────────────────────────────────────────────────────────┘
```

## 五、结论

### 5.1 新架构优势

1. **语义理解提升**：小模型能准确理解"约会"、"亲子"、"休息"等语义标签
2. **延迟降低**：平均 1609ms，比旧架构快 69%
3. **无需硬编码**：10/10 测试都由小模型解析，未触发兜底

### 5.2 待解决问题

1. **无地点查询**：需要提示用户指定位置，或支持全局推荐模式
2. **类别映射**：部分类别（如"餐厅/咖啡"）需要优化映射到数据库类别
3. **零结果问题**：检查空间检索和类别过滤逻辑

### 5.3 下一步优化

- [ ] 支持无地点全局查询模式
- [ ] 优化类别映射（"餐厅/咖啡" → "餐饮美食"）
- [ ] 检查餐饮美食类别的空间检索
- [ ] 扩大默认搜索半径
