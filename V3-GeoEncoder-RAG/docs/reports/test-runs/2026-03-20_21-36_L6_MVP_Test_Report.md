## 性能分析

### 各阶段耗时分布

| 阶段 | 平均耗时 | 占比 |
|------|---------|------|
| 意图解析 | 736ms | 12% |
| 地理编码 | 148ms | 2% |
| 混合检索 | 406ms | 6% |
| 答案生成 | 5118ms | **80%** |
| **总计** | **6408ms** | 100% |

### 瓶颈分析

1. **答案生成 (80%)** - LLM 调用是主要耗时
   - 可优化：流式输出、缓存常见回答
   - 或使用更快的模型

2. **意图解析 (12%)** - LLM 调用
   - 可优化：规则优先 + LLM 兜底
   - 缓存常见查询模式

3. **混合检索 (6%)** - 数据库查询
   - 当前 400ms，可用 FAISS 优化到 <50ms

## 修复记录

### 本次修复

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| 汉口火车站找不到 | SQL 查询了不存在的 `address` 列 | 移除 `address` 列引用 |
| 类别提取干扰 | "华中科技大学"的"大学"匹配到"教育" | 先提取地点名，再从剩余文本提取类别 |
| "周围"不匹配 | 正则只支持"附近/周边/旁边" | 新增"周围/边上/隔壁" |

### 代码变更

1. **geocoder.js** - 移除 `address` 列查询
2. **llmService.js** - 优化类别提取逻辑，排除地点名干扰
