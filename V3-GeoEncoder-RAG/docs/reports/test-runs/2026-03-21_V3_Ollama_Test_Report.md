## 五、性能分析

### 5.1 耗时分布

| 阶段 | 平均耗时 | 占比 |
|------|---------|------|
| 意图解析 | ~800ms | 11% |
| PostGIS 空间过滤 | ~80ms | 1% |
| LLM 回答生成 | ~6,000ms | 82% |
| 其他 | ~400ms | 6% |

### 5.2 瓶颈分析

1. **LLM 回答生成**占 82% 时间，是主要瓶颈
2. 意图解析约 800ms，可接受
3. PostGIS 空间过滤极快 (<100ms)

### 5.3 Fallback 触发分析

两个 fallback 触发点:
1. **测试 #1 "武汉大学"**: 单纯地点名，无类别，模型输出思考过程而非 JSON
2. **测试 #7 "武汉大学附近适合约会的咖啡店"**: 复杂查询，可能 JSON 格式问题

3. **缓存热门查询**: 对高频查询缓存结果

## 七、启动方式确认

### 启动命令
```bash
cd V3-GeoEncoder-RAG && npm run dev
# 或
cd V3-GeoEncoder-RAG && npm start
```

### 自动启动流程
1. `server.js` 启动时调用 `startOllama()` (来自 `ollamaService.js`)
2. 检查 Ollama 是否运行，未运行则自动启动 `ollama serve`
3. 预加载 FAISS 索引 (615K POI embeddings)
4. 服务监听 3300 端口

### 与 LM Studio 的区别

| 特性 | LM Studio | Ollama |
|------|-----------|--------|
| 手动启动 | 需要 | **自动启动** |
| 模型管理 | 手动下载 | `ollama pull` |
| API 兼容 | OpenAI | OpenAI 兼容 |
| 服务常驻 | 需保持窗口 | **后台服务** |
